### **Part 1: Digital Logic & FPGA Fundamentals (Episodes 1–4)**

#### **Episode 1: I'm Rebuilding the 6502 from Scratch, One Gate at a Time**
- **URL:** *Not specified in source transcripts (noted as linked in video description)*
- **Key Learnings:**
  - **Microcontroller vs FPGA:** A microcontroller executes sequential software instructions, whereas an FPGA configures raw hardware logic cells into dedicated digital circuits.
  - **Hardware Platform:** Introduction to the Tang Nano 20K board featuring a Gowin FPGA (20,736 logic cells), a 27 MHz crystal oscillator, six onboard LEDs, and two user push-buttons (S1 and S2).
  - **Toolchain Workflow:** The open-source OSS CAD Suite pipeline: synthesis with **Yosys**, place-and-route with **nextPNR**, bitstream packing with **gowin_pack**, and FPGA programming over USB via **openFPGALoader**.
  - **Verilog Foundations:** Writing combinational wire assignments (`assign`) for an AND gate, creating physical constraint files (`.cst`) to map signals to pins, and using an `always @(posedge CLK)` sequential block with a 25-bit counter to divide the 27 MHz clock and blink an LED once per second.

#### **Episode 2: How a Computer Adds: I Built an Adder from Just Two Logic Gates**
- **URL:** *Not specified in source transcripts (noted as linked in video description)*
- **Key Learnings:**
  - **Basic Logic Gates & Truth Tables:** Implementing AND (`&`), OR (`|`), XOR (`^`), NAND (`~&`), NOR (`~|`), and XNOR (`~^`) across a 6-wire bus vector.
  - **Binary Representation:** Positional notation and arithmetic carry fundamentals.
  - **The Half Adder:** Building a 1-bit half adder using two gates—an XOR gate for the sum and an AND gate for the carry.
  - **Simulation & Verification Discipline:** Simulating with Icarus Verilog (`iverilog`, `vvp`), writing testbenches (`_tb.v`) with tasks, and adopting the "fail once on purpose" rule to ensure test validity.
  - **Waveform Inspection:** Inspecting signal timing using VCD waveform viewers such as Surfer and GTKWave.

#### **Episode 3: I Built an 8-Bit Adder and Tested Every Possible Addition**
- **URL:** *Not specified in source transcripts (noted as linked in video description)*
- **Key Learnings:**
  - **The Full Adder:** Cascading two half adders and an OR gate to sum three bits: operand A, operand B, and Carry-in.
  - **8-Bit Ripple Carry Adder:** Chaining eight 1-bit full adders (`adder8.v`) where the carry ripples from column 0 through column 7 to form an 8-bit sum and a Carry-out flag.
  - **Exhaustive Testing:** Running all 131,072 possible additions (\\(256 \times 256 \times 2\\)) in simulation to verify 100% test coverage.
  - **Synthesis Insights:** How Yosys maps hand-written logic gates into FPGA Look-Up Tables (LUTs) and dedicated hardware carry chains.
  - **Multiplexers:** Implementing hardware data selection via the ternary operator (`? :`).

#### **Episode 4: How a Chip Remembers: I Built Memory from Scratch, One Bit at a Time**
- **URL:** *Not specified in source transcripts (noted as linked in video description)*
- **Key Learnings:**
  - **D Flip-Flop & Clocking:** Transitioning from combinational logic to sequential memory using D flip-flops that sample data on clock rising edges (`posedge CLK`).
  - **Non-Blocking Assignments (`<=`):** Understanding that all right-hand sides are evaluated with pre-tick values and update simultaneously, allowing clean variable swaps without temporary registers.
  - **Registers & Counters:** Constructing 8-bit registers with load-enable signals (`register.v`) and synchronous counters with reset priority (`counter.v`).
  - **Single-Clock Design Rule:** Pacing slow logic using periodic single-tick enable pulses generated by a timer (`timer.v`) rather than creating divided clock trees.
  - **Finite State Machines (FSM):** Implementing state machines using `localparam` states and `case` constructs (`scanner.v`), establishing the foundation for CPU control sequencers.

### **Part 2: Video Architecture & Graphics Pipeline (Episodes 5–8)**

#### **Episode 5: How a Screen Is Really Drawn: One Pixel at a Time, with Two Counters**
- **URL:** *Not specified in source transcripts (noted as linked in video description)*
- **Key Learnings:**
  - **Raster Scanning Principles:** Progressively drawing a display line-by-line, left-to-right, top-to-bottom, matching CRT electron beam timing.
  - **Standard Timing Standards:** 640x480 resolution at 60 Hz requiring 800 horizontal pixel positions (visible, front porch, active-low HSYNC, back porch) and 525 lines (visible, front porch, active-low VSYNC, back porch).
  - **Pixel Clock Derivation:** Calculating the exact 25.2 MHz pixel frequency (\\(800 \times 525 \times 60\\)).
  - **Hardware Raster Engine:** Using nested 10-bit X and Y counters in `raster.v` to compute real-time coordinates and sync pulses.
  - **Combinational Test Pattern Generator:** Generating RGB test patterns (color bars and checkerboard) purely from X/Y coordinates without memory (`pattern.v`), and dumping frames directly to `.bmp` files in testbenches.

#### **Episode 6: The Missing Clock: How a PLL Turns 27 MHz into 25.2 MHz**
- **URL:** *Not specified in source transcripts (noted as linked in video description)*
- **Key Learnings:**
  - **Phase-Locked Loops (PLL):** Synthesising arbitrary clock frequencies from a fixed crystal using analog PLL hardware blocks.
  - **Gowin rPLL Configuration:** Using `gowin_pll` to configure division and multiplication factors: scaling 27 MHz by \\(14/3\\) to 126 MHz, then dividing by 5 with `CLKDIV` to yield 25.2 MHz.
  - **Clock Domain Segregation:** Enforcing strict isolation between asynchronous clock domains ("one clock for each part, nothing crosses without synchronisation").
  - **Hardware Verification:** Testing and timing multiple clock frequencies on real FPGA hardware.

#### **Episode 7: How HDMI Really Works: I Sent a Picture from an FPGA to a Real Monitor**
- **URL:** *Not specified in source transcripts (noted as linked in video description)*
- **Key Learnings:**
  - **HDMI / DVI Physical Layer:** Driving video across four low-voltage differential signaling (LVDS) pairs: Blue, Green, Red, and Clock.
  - **TMDS Encoding Algorithm:** Transition-Minimized Differential Signaling converting 8-bit colour bytes into 10-bit symbols to minimise wire transitions and maintain DC balance.
  - **Sync Embedding:** Encoding HSYNC and VSYNC control signals into reserved 10-bit control characters transmitted exclusively during blanking pauses.
  - **High-Speed Serialization:** Serialising 10-bit data at 252 Mbps per lane using FPGA hard-macro primitives (`OSER10` dual-edge serializers running on a 126 MHz fast clock) and `TLVDS_OBUF` differential output buffers.
  - **End-to-End Display Pipeline:** Combining raster counters, TMDS encoders, serializers, and physical pin constraints to render on a physical HDMI display.

#### **Episode 8: Our 6502 Computer Gets a Video Card: 320x200, 16 Colors**
- **URL:** *Not specified in source transcripts (noted as linked in video description)*
- **Key Learnings:**
  - **Frame Buffer Architecture:** 320x200 graphics scaled \\(2\times2\\) inside 640x480, comprising an 8,000-byte bitmap memory and a 1,000-byte colour attribute memory (\\(40 \times 25\\) grid of \\(8\times8\\) pixel cells).
  - **Palette Mapping:** Replicating the classic Commodore 64 16-colour palette, translating 4-bit nibbles (ink and paper) into 24-bit RGB values.
  - **FPGA Block RAM:** Using `$readmemh` to infer dedicated Block RAM primitives (`SP` blocks) in Yosys.
  - **Memory Pipeline Latency Alignment:** Compensating for the 1-clock-tick read latency of synchronous Block RAM by delaying raster coordinates, sync pulses, and blanking signals by exactly one tick.
  - **Retro Graphics Trade-offs:** The mechanics of "colour clash" when images require more than two colours within a single \\(8\times8\\) character cell.

### **Part 3: 6502 Architecture & Toolchain Setup (Episodes 9–11)**

#### **Episode 9: Our First 6502 Program: Machine Code, Assembled by Hand**

  - **System Memory Map:** Defining address space layout: 32 KB RAM (\$0000–\$7FFF), memory-mapped LED I/O (\$8000), and 16 KB ROM (\\(C000–\\)FFFF).
  - **Writing 6502 Assembly:** Constructing a 5-instruction loop to count on hardware LEDs (`LDA #0`, `STA $8000`, `CLC`, `ADC #1`, `JMP loop`).
  - **Addressing Modes:** Immediate (`#value`), Absolute (`$address`), and Implied.
  - **Manual Assembly:** Encoding instructions into 11 bytes of machine code, strictly adhering to little-endian 16-bit addressing rules (low-byte followed by high-byte).

  - **Linker Configuration Scripts (`memory.cfg`):** Specifying target memory segments (ZEROPAGE, RAM, ROM) and memory areas to generate clean, padded binary images (`count.bin`, `rom.hex`).
  - **Relocation & Symbols:** How assemblers leave unresolved relocatable address markers until the linker determines final physical addresses.
  - **Cycle-by-Cycle Pencil-and-Paper Execution:** Tracing the exact cycle counts of the 11-byte program (STA: 4 cycles, CLC: 2 cycles, ADC: 2 cycles, JMP: 3 cycles = 11 cycles per loop).

#### **Episode 11: ROM, RAM and the Bus for Our 6502 Computer, in Verilog**
- **URL:** *Not specified in source transcripts (noted as linked in video description)*

  - **Address Decoding Logic:** Selecting between RAM and ROM using upper address bits (bit 15 selects RAM; bits 15 and 14 select ROM).
  - **Synchronous Bus Timing & CPU Pacing:** Accounting for 1-tick memory access latency by enforcing a minimum 2-clock-tick execution cycle driven by a `step` pacing input.
  - **FPGA Block RAM Resource Consumption:** Allocating 24 of the 46 available FPGA memory blocks to instantiate 16 KB of ROM and 32 KB of RAM.
